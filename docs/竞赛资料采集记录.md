## 采集与导入原则

1. 官网动态正文通过独立 `agent-browser` 会话读取。只访问公开页面，不登录或提交报名信息。
2. 官方PDF直接下载。蓝桥杯软件赛RAR与服创ZIP只读取选中的PDF，逐文件写到明确的本地目标；不执行附件，不直接展开压缩包内部路径。
3. 网页正文按原文边界截取，剔除导航、页脚和其他学校的校内联系人。信息安全转发通知的错位赛程表整段排除，未手工猜测修正。
4. PDF通过原有 `/api/documents` 接口解析，保留页码。手册43页未截断。网页为原文节选，来源卡片定位段落，不虚构页码。
5. 保留原通知与调整通知，但日期查询仅在所选资料内存在明确同赛事、同届次的替代通知时排除旧日程。查询资格仍可使用原通知。仅选择旧文件时仍展示旧文件，使用者须核对标题、年份、阶段。
6. 当前默认关键词检索与智谱免费文本模型，不启用付费嵌入，不改密钥存储方式。原文数据不提交Git。

## 批量导入和验证

先按清单下载并核对对应资料，按 `file` 字段放入本地采集目录，再启动本机服务：

```powershell
npx tsx scripts/import-competition-sources.ts
npx tsx scripts/validate-competition-sources.ts
```

导入脚本先检查全部文件的正文边界、类型和大小，再使用现有接口逐份导入。接口遇到相同正文及元数据返回重复，不新增文档。脚本不会自动抓取网站。评委从GitHub克隆后，本地数据目录为空，需要自行取得附件再导入。

验证脚本会使用本机配置的模型，将相关原文片段发给模型服务；本次执行已获用户授权。完整结果留在 `artifacts/competition-validation.json`，须人工对照答案与来源；原文回退单独统计，不算模型正确作答。

## 后续开发顺序

1. 补齐操作系统设计赛的官方完整规则，以及人工智能创意赛的分赛道材料。
2. 将本轮核对到的学生人数、教师人数、是否跨校、学生层次、技术平台要求和阶段日期建成审核过的结构化字段，绑定具体原文与届次。
3. 由程序计算人数、过滤届次、区分全国和校内截止日期、执行明确的资格条件；AI解释依据与尚未确认的条件。
4. 再做“按专业、年级和技能推荐比赛”的入口。缺失条件标记待确认，不判定为已符合资格。

在结构化字段审核完成前，复杂资格判断和跨赛事比较仍需人工查看原文。现有冲突回退规则只覆盖已识别出的模式，不是全面事实校验。
