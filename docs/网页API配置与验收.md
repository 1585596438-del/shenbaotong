# 网页 API 配置与验收

2026-10-09：工作台的“运行设置”新增 API 接入表单。用户可以选智谱、DeepSeek，或填写其他兼容接口及本机服务的基础地址；模型名称由用户按账号权限填写，不把聊天模型当作嵌入模型。

## 使用

1. 打开“运行设置”，选择服务商并填写基础地址、聊天模型名称和 API 密钥。
2. 点击“测试聊天连接”核对真实连接；测试不会保存配置。
3. 如需向量检索，开启“配置向量检索”，填写嵌入模型名称。可沿用聊天地址与密钥，也可填写独立的嵌入地址和密钥。
4. 点击“保存 API 配置”，后续请求立即使用新配置，无需重启服务。已开始的请求继续使用它开始时的配置。
5. 启用嵌入服务后，进入资料库为文档建立索引。更换嵌入地址或模型后需要重新索引；原文仍可关键词检索。

留空密钥保留已有配置，输入新密钥可替换；更换服务来源时必须提供新服务密钥，原密钥不会被自动送到新服务。HTTP 地址仅允许本机 localhost、127.0.0.1 和 ::1；其他服务使用 HTTPS。基础地址不能带账号密码、查询参数或具体的 `/chat/completions`、`/embeddings` 后缀。

## 保存边界

初次使用读取环境配置，既有智谱设置保持可用。网页保存后，六项实际参数原子写入 `RAG_DATA_DIR/model-settings.json`（默认 `data/model-settings.json`），覆盖环境默认值。文件包含本机密钥，沿用当前单人本地工作区的存储方式；不提供云端加密或多人权限管理。`data/` 已被 Git 忽略，不提交密钥、配置文件、用户聊天和数据库。

读取设置只返回服务地址、模型名和密钥是否存在，绝不回传已存密钥；前端不把密钥放入 localStorage。修改、测试请求校验本地 Origin，正文限制为实际 16KB，并拒绝非法字段或 JSON。模型接口错误只返回状态说明，不回显服务方响应正文、密钥或内部错误。

`GET /api/settings` 读取脱敏配置；`PUT /api/settings` 保存配置；`POST /api/settings/test` 使用候选配置测试指定聊天或嵌入服务。测试会真实发送一条短请求，费用及可用性取决于所选服务，但不会写配置、聊天或文档。测试成功不代表其他模型或后续额度可用。

## 验收

- 回归 102/102、类型检查和正式构建通过。
- 临时目录与模拟 HTTP 模型服务验证：环境配置兼容、留空密钥保留、即时切换模型、嵌入地址/密钥继承、向量模型变更标识、跨站/过长/非法字段拒绝、换服务密钥保护，以及失败不覆盖旧配置。
- 网页独立测试：选择 DeepSeek 后地址更新，放弃修改恢复；聊天和嵌入连接成功，嵌入返回 3 维测试向量；错误模型显示 HTTP 404；保存后刷新恢复模型及开关，密钥输入框保持为空。
- 实际网站只读验证：仍使用原来的 `glm-4-flash-250414`，密钥已配置，35 份资料保留；没有写入真实 `data/model-settings.json`，没有替换用户密钥或请求外部模型。
- 桌面及 390px 手机截图人工检查通过；手机页面无横向溢出，表单与按钮可操作。
