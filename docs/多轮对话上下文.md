# 多轮对话上下文

2026-10-09完成。本次从“上一问关键词追问”扩展到同一会话的多轮user/assistant上下文。

## 行为与用量

- 向聊天接口发送按顺序排列的历史用户、助手消息，当前问题与本次原文证据最后发送。服务器读取保存的会话，不依赖浏览器回传历史正文。
- 最多最近8轮、总计6000字符；单条用户问题最多1000、旧回答最多1200字符。优先保留较新完整消息对，不重复发送旧引用文本。完整聊天记录继续保存在SQLite，但不全部送给模型。
- 检索从近期用户消息找赛事锚点，再继承赛道、赛区和年份。明确新赛事或新赛项覆盖旧主题；年份追问覆盖之前的年份。中间问题没有证据时，后续追问仍可找到近期已明确的赛事。
- 从用户问题提取主题，避免递归拼接前一条已扩展的检索问题；短追问突出当前条件。保留旧的previousAnswerId调用方式，新会话不继承其他会话。
- 用户明确自述的专业、年级等可以确认和回忆，显示“对话记忆”。比赛报名、费用、人数与资格仍走原文检索，不能借个人记忆模式免除引用。
- 旧助手回答可能有误，只用于理解对话，不能替代本次证据；旧片段ID不能作为本次范围的引用。切换文档范围仍限制可用来源。
- 聊天模型、密钥和本机向量索引保持现有配置。没有额外的模型请求来重写问题；上下文只增加当前聊天请求中的有限文本。用户选择的模型服务仍按自身账户规则计费。

## 验证

新增测试覆盖实际兼容接口的messages角色、顺序、长度上限与最近8轮裁剪。临时数据库多轮流程：

1. 自述“我是计算机专业的大二学生”。
2. 问2026年蓝桥杯Python组队。
3. 提问未收录的纪念餐券。
4. 关闭并重开数据库，再问“指导老师呢”，仍限定Python与2026。
5. 问“那Java呢”，切换至Java规则。
6. 问2027年的指导老师，切换年份。
7. 询问之前说的专业，只复述用户自述，不引用比赛原文。
8. 换到软件杯，原文范围不混入蓝桥杯。
9. 模型用空引用回答指导老师人数时，被拒绝并回退原文。
10. 新建聊天没有其他聊天的历史消息；显式选择其他赛事资料后，不返回范围外旧引用。

测试使用模拟模型及临时资料库，不写入用户聊天，不调用智谱生成。完整回归110/110通过，类型检查和生产构建通过。标准多轮消息传递和检索规则已验证，实际措辞仍取决于用户的聊天模型。

生产网页已重启；浏览器打开现有4轮聊天后显示“支持连续追问”，刷新仍恢复同一聊天与4轮消息。状态接口确认38份资料和向量索引、用户的智谱聊天模型与本机嵌入配置均保留。网页验证只读，没有向正式聊天发送测试消息。
